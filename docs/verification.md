# Проверка переноса на Rust

Дата: 28 октября 2026 года. Локальная среда: Windows AMD64, Rust 1.99.1, Cargo 1.99.1. Проверен текущий `Cargo.lock`.

| Проверка | Результат |
| --- | --- |
| `cargo fmt --all --check` | Форматирование соответствует rustfmt |
| `cargo clippy --locked --all-targets -- -D warnings` | Без предупреждений |
| `cargo test --locked --all-targets` | 34 теста: 19 модульных, 6 CLI, 9 сетевых интеграционных |
| `cargo build --release --locked` | Собран Windows AMD64 executable |
| `tests/installer.ps1`, PowerShell 7 | 8 сценариев прошли |
| `tests/installer.ps1`, Windows PowerShell 5.1 | Те же 8 сценариев прошли |
| Реальные HTTPS trace / `lock` / `status` | Определение IP, проверка TLS и совпадение IP прошли в изолированном временном каталоге |
| 170 registry-зависимостей из `Cargo.lock` через OSV | На момент запроса совпадающих advisory не получено |

Сетевые тесты проверяют запрет исходящего подключения при несовпадении IP и недоступном измерителе; закрытие обоих концов CONNECT; отмену HTTP-потока; отзыв допуска во время upstream handshake; работу фонового монитора; сохранение ранних байтов, метода, тела и query; удаление служебных заголовков; отсутствие прямого fallback после отказа выбранного прокси.

CLI-тесты запускают настоящий исполняемый файл, проверяют конкурирующие обновления конфигурации, ошибки с ненулевым кодом, занятый порт, готовность и штатную остановку фонового процесса. Подделка control-токена не останавливает работающий процесс; устаревший PID не используется для уничтожения процесса.

Дополнительно проверены открытие справки без создания состояния, отсутствие ANSI в pipe и при `NO_COLOR`, явные `--color always/never` для команд, справки и ошибок. Установщик проверен с локальными архивами: установка, неверный/дублированный SHA256, обновление, загруженный ScriptBlock, точная форма `irm | iex`, отказ от Go-релиза и отсутствие assets. Полный вызов `irm | iex` в тесте доходит до проверки контрольной суммы и намеренно останавливается на несовпадении, не затрагивая рабочую установку и PATH. Успешная установка скачанного скрипта проверена с `-NoPathUpdate` в отдельный каталог.

Проверка зависимостей выполнена через официальный [OSV batch API](https://google.github.io/osv.dev/post-v1-querybatch/) по именам и точным версиям. Нулевой результат отражает доступные записи базы, а не доказательство отсутствия уязвимостей.

Рабочие системные PAC-настройки и автозапуск пользователя при проверках не менялись. Восстановление состояния PAC проверено на сериализованной модели; настоящая работа реестра, автозапуска при входе, браузеров и конкретного VPN требует отдельного испытания. Удалённые GitHub Actions для Linux/macOS/ARM64 настроены, но из этой рабочей среды не запускались. Реальные аккаунты и ключи API в тестах не использовались.
